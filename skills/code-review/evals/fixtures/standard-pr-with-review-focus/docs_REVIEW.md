# payment-api コードレビュー観点

## セキュリティ
- SQL クエリは **必ず** parameterized query を使う。文字列連結での SQL 組み立ては禁止
- 外部入力（HTTP リクエスト、DB、外部 API レスポンス）は使う前にバリデーションする
- ログに個人情報・決済情報・認証情報を含めない

## エラーハンドリング
- エラーは `fmt.Errorf("...: %w", err)` で wrap して context を保持する
- `err` を握り潰さない（`_ = err` は禁止。ログ or 再 return が必須）
- panic は使わない（プロセス起動時の初期化失敗のみ許可）

## データ整合性
- 金銭に関わる処理は必ず database transaction の中で実行する
- 1 つのユースケース内で複数テーブルを更新する場合、トランザクション境界を明示的に管理する
- SELECT 後に UPDATE するパターンは `SELECT ... FOR UPDATE` で排他を取る

## 可読性
- ハンドラーはビジネスロジックを持たない。薄く保ち、service 層に委譲する
- マジックナンバーは定数化する
